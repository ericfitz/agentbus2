# Milestone 1: Repository Skeleton and Done Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go module whose `make verify` builds, vets, formats, lints, checks generated-code freshness, runs unit tests and runs the (empty) Store and Bus conformance suites against SQLite and Postgres, locally through testcontainers and in CI through a Postgres service container, and fails when Postgres is unreachable.

**Architecture:** One Go module at the repository root (`main.go` for the `agentbus2` binary, packages under `internal/`). A stub OpenAPI 3.1 document under `api/` is generated by oapi-codegen v2.8.0 (pinned with a `go.mod` `tool` directive) into `internal/gen`, and CI fails on a stale `internal/gen`. A test-only package `internal/dbtest` hands both engines to the conformance suites: SQLite in a temp file, Postgres from `AGENTBUS2_TEST_POSTGRES_DSN` or, when it is unset, from a testcontainers-go Postgres container started once per test binary. Nothing in the test wiring may skip: an unreachable Postgres is a test failure. A gate-check script proves the negative halves on every `make verify`: an unreachable Postgres fails the suites, the variable unset with no Docker reachable fails them (the suite binaries are cross-compiled for Linux and run inside a `busybox` container that has no Docker socket and no network), a changed schema changes the generated code. A committed self-test mutates a throwaway worktree and proves each gate check, the CI negative-gate script and the CI simulation actually fire. CI runs the same gate on a Postgres service container and, as a second proof of the no-Docker path, in a job that stops the runner's Docker.

**Tech Stack:** Go 1.27 (`go 1.27` directive; oapi-codegen v2.8.0 needs 1.25 or newer), `CGO_ENABLED=0`, `modernc.org/sqlite` v1.60.1, `github.com/jackc/pgx/v5` v5.11.0 (stdlib driver `pgx`), `github.com/testcontainers/testcontainers-go` v0.44.0 with `modules/postgres` v0.44.0, `github.com/oapi-codegen/oapi-codegen/v2` v2.8.0 (`tool` directive) and `github.com/oapi-codegen/runtime` v1.7.0, golangci-lint v2.14.0, GitHub Actions with a `postgres:17` service container.

**Spec:** `docs/superpowers/specs/2026-10-19-agentbus2-design.md` (section 10, Milestone 1; sections 5.3, 7 and 8 for the libraries, the generator and the done gate), ADR 0004 (Decisions 28, 50, 53, 54), ADR 0005 (Decisions 31, 32, 33), ADR 0007 (Decision 64, pinning and freshness), and the codegen spike `docs/superpowers/specs/2026-10-19-codegen-spike.md` (need 8, pinning and freshness; `oapi/cfg.yaml` for the generator configuration).

## Global Constraints

- Module path `github.com/ericfitz/agentbus2`; `go 1.27`; every build and test runs with `CGO_ENABLED=0` (Decision 53; spec section 5.3).
- Libraries are `database/sql` with `modernc.org/sqlite` and `pgx` through its stdlib adapter (Decision 50); no ORM, no sqlc. `sqlx` is not needed before Milestone 2 and is not added here.
- The generator is oapi-codegen v2.8.0, `std-http-server` + `strict-server` + `client` + `models`, pinned by a `tool` directive in the main `go.mod` and run through `go tool` (Decision 64; ADR 0007). Generated code lives in `internal/gen`; `make generate` regenerates it; CI fails when it is stale (spec section 7 and 8).
- `make verify` is the done gate: build, vet, gofmt, lint, unit tests, and both conformance suites against both engines. A run that skips the Postgres suites is not a pass (Decision 28; project `CLAUDE.md`). Postgres comes from testcontainers unless `AGENTBUS2_TEST_POSTGRES_DSN` names an existing server; CI uses a service container (Decision 53).
- Names and paths are `agentbus2` throughout: binary `agentbus2`, environment prefix `AGENTBUS2_` (Decision 33). The binary is git-ignored at `/agentbus2`, and `HANDOFF.md` and `.local/` stay git-ignored (already in `.gitignore`, ported from v1 `.gitignore`).
- Every porting commit names its v1 source file (Decision 31). v1 lives at `/Users/efitz/Projects/agentbus`.
- Work lands directly on `main`; no PRs; nothing is pushed to origin during this milestone (task instruction). Commit messages follow v1's Conventional Commits style (`build:`, `feat:`, `test:`, `ci:`, `docs:`) and end with the attribution trailer the session's instructions give.
- Unrecognized inputs are rejected with a test (global rule): an unknown subcommand, a malformed Postgres DSN, a `dbtest.Engine` whose name or driver is not one of the two known pairs.
- Shell beyond a one-liner goes in a script run with `bash` under `set -euo pipefail` using absolute paths derived from the script's own location.

## Choices this milestone makes (delegated by the spec, recorded with rationale)

Spec section 10 names the deliverables but leaves the layout and the test wiring to this plan. These are Claude's choices; none re-decides a numbered decision.

1. **Negative check mechanism.** The task suggested proving the gate by pointing `DOCKER_HOST` at nothing. That alone does not work: testcontainers-go v0.44.0 `internal/core/docker_host.go` `extractDockerHost` tries `DOCKER_HOST`, finds it unreachable, and continues to the default socket `/var/run/docker.sock`; a probe on 2026-10-20 with `DOCKER_HOST=tcp://127.0.0.1:1` started a `postgres:17` container in 11.6 s. The two negative halves are therefore proven locally, on every `make verify`, by two different mechanisms in `scripts/check-gates.sh` (Task 6):
   - *Variable set, server unreachable* (check 1): the override variable pointed at `postgres://agentbus2:agentbus2@127.0.0.1:1/agentbus2?sslmode=disable&connect_timeout=2`, which also proves the override is honored and never falls back to Docker.
   - *Variable unset, no Docker* (check 5, `postgres-no-docker-fails`): each suite package is cross-compiled with `CGO_ENABLED=0 GOOS=linux go test -c` and the static binary runs inside `docker run --rm --network none ... busybox:1.37.0`, where there is no Docker socket, no `DOCKER_HOST`, no `XDG_RUNTIME_DIR`, no `~/.testcontainers.properties`, no network and no host environment (so the variable is unset). The real `startPostgresContainer` then runs and must fail. A probe on 2026-10-20 ran exactly this (`postgres.Run(ctx, "postgres:17")` in a busybox container) and it failed in 0 s with `run postgres: generic container: get provider: rootless Docker not found, failed to create Docker provider`: the path fails fast, it does not hang, and the two-minute `startTimeout` is only the backstop.
   A unit test of `resolve` with an injected failing starter (Task 4) is the third, pure proof that a start failure is wrapped in the exact text and never skipped. CI runs the same gate (its `verify` job runs `make verify`, so check 5 runs there too) and adds a second end-to-end proof of the no-Docker path: the `gate-negative-no-docker` job (Task 7) stops the runner's Docker socket and daemon, leaves the variable unset, and requires `make verify` to fail with the unset-and-could-not-start text and no `verify: OK`.
   Consequence, accepted: check 5 needs a working Docker on the host that runs `make verify`, even when `AGENTBUS2_TEST_POSTGRES_DSN` names an external server (busybox, not Postgres, is what it starts). Every path this plan documents already has Docker (developer machines, all CI jobs, `ci-sim.sh`); `make test-conformance` with the variable set stays Docker-free. This changes the gate's stated prerequisites, so it is also listed under "pending Eric".
2. **Unit tests and conformance suites are split by package path, not build tag.** `make test` runs `go test` on every package except `internal/conformance/...`; `make test-conformance` runs `go test -count=1 -p 1 ./internal/conformance/...`. No build tag, so `go vet ./...` and `golangci-lint run ./...` compile the suites with no extra flags. `-count=1` because Go's test cache keys on environment variables and files, not on whether Postgres answers, so a cached pass could mask an unreachable server; `-p 1` so the two suite binaries start their containers one at a time.
3. **Container lifetime.** One Postgres container per test binary, started lazily on the first request through `sync.Once`, terminated by `dbtest.Run(m)` from each suite package's `TestMain`; testcontainers' Ryuk reaper is the backstop for a killed process. Image `postgres:17` (the probe used it; CI's service container uses the same tag).
4. **Empty variable counts as unset.** `AGENTBUS2_TEST_POSTGRES_DSN=""` behaves as unset, because CI `env:` blocks and `make` commonly pass empty strings; any non-empty value is used as given and must be a reachable server.
5. **Generated-code freshness is part of local `make verify`** as `generate-check` (regenerate, then fail if `git status --porcelain --untracked-files=all -- internal/gen` prints anything: modified, staged, deleted or untracked), not CI-only: the exit criterion says `make verify` runs end to end locally and in CI, the CI `verify` job just runs `make verify`, and the milestone's task text names "the CI freshness diff" as a deliverable. `tidy-check` has no such backing in the spec or the task, so it is the one addition left pending Eric (below); both extend the CLAUDE.md gate list, and the asymmetry is deliberate.
6. **The stub schema** is OpenAPI 3.1.0 with the one operation Decision 43 fixes, `GET /.well-known/agentbus2` (`security: []`, response `WellKnown {discover: string}`), nothing else, and no security schemes. Milestone 4 writes the real document and may keep or rewrite this operation. The stub does not discharge Milestone 4's 3.1 re-test (no validator runs here). `embedded-spec` is off; Milestone 4 turns it on if it adopts the validator middleware.
7. **`main.go` at the module root** (as v1), building to `./agentbus2`; `internal/version.Version` holds the version string (v1 keeps it in `internal/mcpserver/server.go:28`, which v2 has no reason to copy). `agentbus2` with no arguments prints usage and exits 2; an unknown subcommand is rejected the same way.
8. **`make test-race`** is `go test -race -count=1 ./...`, every package including the suites, so it needs Postgres like `verify` does; it is not part of `verify` (CLAUDE.md lists it separately).
9. **SQLite in tests** opens a plain file path under `t.TempDir()`. v1's `SQLiteDSN` and `sqliteURIPath` (`internal/bus/bus.go`, tests in `internal/bus/dsn_test.go`) carry Store settings (`_txlock=immediate`, busy timeout) and are ported with the Store in Milestone 2, not here.
10. **CI** is a new workflow (v1 has no `ci.yml`); it borrows only v1 `release-build.yml`'s convention of pinning actions by commit SHA.

## Review Focus

1. `AGENTBUS2_TEST_POSTGRES_DSN` set to a syntactically invalid value (`not-a-dsn`): the suite must fail naming the variable with the "could not be opened" text, before any connection attempt, without printing the value, and never fall back to Docker. `sql.Open("pgx", ...)` does not parse the DSN (pgx v5.11.0 `stdlib/sql.go:348` returns a connector without parsing; the parse runs in `Connect`, so the error would otherwise surface only at ping time as "unreachable", the wrong remediation hint). `openDB` therefore parses with `pgx.ParseConfig` first. (Test in Task 4.)
2. `AGENTBUS2_TEST_POSTGRES_DSN` set but empty: treated as unset; the container path runs. (Test in Task 4.)
3. A file appearing in `internal/gen` that generation does not produce (an untracked stray or a renamed output): `generate-check` must fail, not only on modified tracked files. (Test in Task 3.)
4. `make test` accidentally including the conformance packages after a path change: `make test` must pass with `AGENTBUS2_TEST_POSTGRES_DSN` pointed at an unreachable server, proving no conformance package leaked into the unit set. (With the variable set Docker is never consulted, so this check says nothing about Docker; `make test` needs no Docker because no package it runs asks `dbtest` for Postgres.) (Check `unit-tests-exclude-conformance` in Task 6's script.)
5. The container start hanging (Docker present but wedged): the start is bounded by a two-minute context so the failure is a message, not `go test`'s ten-minute panic. (Bound set in Task 4; a unit test with a 50 ms bound and a starter that blocks on `ctx.Done()` pins the behavior.)
6. The variable unset and no Docker reachable at all: the real `startPostgresContainer` must fail with the unset-and-could-not-start text, `TestScaffold/sqlite` must still pass and nothing may skip. (Check 5 in Task 6's script, run in a `busybox` container with no socket and no network; the CI `gate-negative-no-docker` job is the second proof.)
7. The gate harness itself: every `check-gates` check, `ci-gate-negative.sh` and `ci-sim.sh` must be shown to fire on a real mutation, by a committed self-test, before the milestone is called done (Definition of Done C). (Task 8.)

Port the v1 target shapes. Targets and their exact recipes:

```make
.PHONY: build build-all vet fmt-check lint test test-race tidy-check
export CGO_ENABLED=0
PKGS_UNIT = $$(go list ./... | grep -v '/internal/conformance')

build:       ## Build the agentbus2 binary (no cgo), as the release build will
	go build -trimpath -o agentbus2 .
build-all:   ## Compile every package
	go build ./...
vet:
	go vet ./...
fmt-check:   ## gofmt over this module's Go files (files, never directories: gofmt recurses into a directory argument)
	@out=$$(gofmt -l $$(go list -f '{{range .GoFiles}}{{$$.Dir}}/{{.}} {{end}}{{range .TestGoFiles}}{{$$.Dir}}/{{.}} {{end}}{{range .XTestGoFiles}}{{$$.Dir}}/{{.}} {{end}}' ./...)); if [ -n "$$out" ]; then echo "gofmt needed:"; echo "$$out"; exit 1; fi
lint:        ## golangci-lint v2 default linters (no .golangci.yml)
	golangci-lint run ./...
test:        ## Unit tests: every package except internal/conformance (no Docker needed)
	go test $(PKGS_UNIT)
test-race:   ## Every package under the race detector, suites included (needs Postgres like verify)
	go test -race -count=1 ./...
tidy-check:  ## go.mod and go.sum are tidy (CI step; not in verify, pending Eric)
	go mod tidy -diff
```

`fmt-check` passes `gofmt` the module's Go files, not its package directories: `gofmt -l <dir>` recurses (verified: a directory argument reported a file three levels down), and `go list -f '{{.Dir}}' ./...` includes the module root because `main.go` makes `.` a package, so a directory list would walk `docs/superpowers/specs/2026-10-19-codegen-spike/` (two other modules, plus their git-ignored `gen/` and `probes/` output once `run.sh` has run) and `.worktrees/`, making the gate depend on untracked, out-of-module content. The file template (`GoFiles`, `TestGoFiles`, `XTestGoFiles`; `$$.Dir` and `$$(...)` are make escapes for `$.Dir` and `$(...)`) was run against the v1 module on 2026-10-20: 68 files, exit 0. `PKGS_UNIT` drops the trailing slash from its `grep -v` so that the doc-only package `internal/conformance` itself is excluded as well as its two suite packages.
