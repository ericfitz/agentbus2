# Milestone 4: OpenAPI, Generated Server and Client, Local Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The real OpenAPI 3.1 document in `api/` with both security schemes (Decision 65), regenerated into `internal/gen` by the pinned oapi-codegen v2.8.0 (Decision 64), hand-written `net/http` handlers over the Milestone 3 core with `application/problem+json` for every error the framework or the core produces (Decision 46, spec 3.3), the `Idempotency-Key` header mapped onto the core's receipts (Decision 66), discovery at `/.well-known/agentbus2`, `GET /v1/discover` and `/.well-known/openid-configuration` (Decisions 43, 65, 91), non-blocking `receive` and the long-poll `GET /v1/sessions/{session}/watch` with 200, 204 and 409 `replaced` (Decisions 42, 45, 68, 83), the in-process `http.RoundTripper` (Decision 35), a remote `Bus` over the generated client that keeps generated types behind the `Bus` interfaces (Decision 47), and an `agentbus2 server` command that serves over SQLite or Postgres and refuses every authenticated operation until Milestone 5. Exit: generation and the kin-openapi request validator pass on the real 3.1 document; the Milestone 3 core/`Bus` conformance suite passes through the generated client over the in-memory transport on both engines, beside its local run; a stale `internal/gen` fails CI; a newer watch replaces an older one with 409, also across two processes sharing one SQLite file (v1 issue ericfitz/agentbus#39).

**Architecture:** `api/openapi.yaml` is the one source of the wire protocol; `make generate` writes `internal/gen/gen.go` (`std-http-server`, `strict-server`, `client`, `models`) and `internal/gen/spec/spec.go` (`embedded-spec` only, a second config, so the kin-openapi validator and `GET /v1/discover` read the same document while clients never link it). `internal/server` builds one `http.Handler` from a `*core.Core`: an `Authenticator` seam that only attaches an identity to the request context (`RefuseAll` until Milestone 5; `InProcess` for the in-memory transport of Decision 35), the `oapi-codegen/nethttp-middleware` validator that enforces the document's security requirements and parameter and body schemas, the generated router with the three strict-server hooks, and one `WriteProblem` that every hook and every handler error goes through. Handlers are thin: identity from the context, generated request to `bus` input, one Milestone 3 `Service` call, `bus` result to generated response; every failure is returned as the error and becomes a problem with the status of its `bus.Code`. `internal/bus/remote` implements the five `Bus` interfaces over `gen.ClientWithResponses`, converting generated types to domain types and problems to `*bus.Error`. `internal/server/cmd` is the `agentbus2 server` command: store, `EnsureGeneral`, the maintenance loop, an `http.Server` whose timeouts allow a 50 s long-poll. The conformance suite's `newBus` factory is switched by `AGENTBUS2_BUS_TRANSPORT` between `local.New` and the remote `Bus` over the in-process transport, and `make test-conformance` runs the `bus` package once per transport.

## Global Constraints

- Module `github.com/ericfitz/agentbus2`, `go 1.27`, `CGO_ENABLED=0`; every method takes a `context.Context` (Decision 6). Work lands on `main`, nothing is pushed in this milestone, Conventional Commits with the session's attribution trailer; each task commits only its own files, listed by path in its commit command (never a directory).
- Decision 47 as a build rule: `internal/bus`, `internal/core/...` and `internal/bus/local` never import `internal/gen`, `internal/gen/spec` or `internal/server`; `internal/bus/remote` imports `internal/gen` and `internal/bus` and nothing under `internal/server`, `internal/core` or `internal/gen/spec` (so no client binary links kin-openapi); `internal/server` imports `internal/gen`, `internal/gen/spec`, `internal/bus`, `internal/core/...` and never `internal/bus/local` or `internal/bus/remote`. The rule covers production imports: Task 11's `scripts/m4-exit-checks.sh` checks the three with `go list -deps` (without `-test`, so `_test.go` files are outside it; `internal/conformance/bus` imports `local`, `remote` and `server` together by design).
- The document is OpenAPI 3.1.0 (Decision 65) written with no 3.1-only idiom: no `type: [T, "null"]`, no `const`, no `$schema`, no webhooks; an optional member is absent from the JSON, never `null` (the generated field is a pointer). Rationale: that is exactly what the planning probe covered, and the validator and generator are only known to work on that subset.
- Every error on the wire is `application/problem+json` (spec 3.3): the body-limit middleware's 413, the three strict-server hooks, the validator's `ErrorHandlerWithOpts`, and every handler error share `server.WriteProblem`. A `text/plain` body with a status of 400 or more anywhere is a bug and Task 2's `TestEveryFrameworkErrorIsProblem` fails on it.
- Unrecognized inputs are rejected with a test: an unknown `AGENTBUS2_BUS_TRANSPORT` value (Task 4's Step 4 run, re-run on every `make verify` by check 6 of `scripts/check-gates.sh`, with self-test block 13), an unknown `-store` engine flag combination (Task 9's `TestRunFlags`), a nil `Authenticator` means `RefuseAll` (never accept-all; Task 2's `TestNilAuthenticatorRefuses` calls `New(e.core, Options{})` directly, because the test fixture's own default is `InProcess{}`), an enum value outside the document (the validator's 400 carries code `validation`, the same code the core gives, so the suite behaves identically through both transports).
- The Milestone 1 and 3 gate checks stay in force: no `.Skip(` under `internal/conformance` or `internal/dbtest`; `make test` is Docker-free, so `internal/server`, `internal/server/cmd` and `internal/bus/remote` unit tests open SQLite through `sqlite.Open` on a temp path; both-engine coverage lives in `internal/conformance/bus` only.
- `scripts/check-gates.sh` check 4 mutates the line `^        discover:$` of `api/openapi.yaml` and regenerates the mutated document through `api/oapi-codegen.yaml` only; the real document keeps the `WellKnown` schema's `discover` property at that indentation (`grep -c '^        discover:$' api/openapi.yaml` prints `1`, asserted in Task 1), and the models config stays the one check 4 mutates through. Task 1 adds to check 4 an unmutated regeneration through `api/oapi-codegen-spec.yaml` compared with `internal/gen/spec/spec.go`, with its own self-test block `gen-spec-hand-edited`, because `make generate-check` depends on `generate` and so overwrites an uncommitted hand edit before it looks at `git status` (it catches a stale committed file in CI, which is its job, but it cannot be the self-test's negative proof). Task 4 adds check 6 `transport-env-rejects-unknown` and Task 11 self-test block 13 for it.
- Timeouts: no `http.Server.WriteTimeout` and no client `http.Client.Timeout` below 60 s on any path a `watch` crosses (the server caps the wait at `WatchMaxSeconds` 50; a transport timeout under it would turn a timeout into an error). `ReadTimeout` is not such a timeout (choice 15).
- Identity on the context travels under two keys (choice 5): the in-process transport sets `inprocIdentity`, read only by `InProcess.Authenticate`; the auth middleware always sets `identity` (to `""` when the authenticator returned none), the one key `IdentityFrom` and the validator's `AuthenticationFunc` read.
- Definition of Done D applies to Task 9 (`Serve` start-up: second run, two servers on one store, a start after a crash).

Thirty operations carry the global security requirement and three (`wellKnown`, `openidConfiguration`, `discover`) declare `security: []`.
2. **`Idempotency-Key` is an optional header** (`required: false`) on every operation marked IK, and "absent or empty" means "no receipt", exactly as `core.WithReceipt` treats `key == ""`; the remote `Bus` sends the header only when the input's `IdempotencyKey` is non-empty. Rationale: v1's `idempotency_key` is `omitempty` and the Milestone 3 suite calls `Send`, `Edit`, `Create` and the rest with empty keys in most tests; a required header would make the remote `Bus` mint keys, store a receipt per call and make the suite behave differently through the client than locally, which would hollow out the exit criterion. The spike's sample made it required only to prove the binder (need 4). Pending item 1 records the departure from that sample.
3. **Error codes on the wire.** The `Problem.code` enumeration in the document is Milestone 3's eleven codes (`validation`, `not_found`, `conflict`, `forbidden`, `not_registered`, `rate_limited`, `replaced`, `session_lapsed`, `session_closed`, `unavailable`, `internal`) plus one the HTTP layer needs for a failed security requirement (spec 3.3 names it as a framework error that must be problem+json): `unauthenticated`, added to `internal/bus/errors.go` as `CodeUnauthenticated` (401, `Retryable false`) in Task 1, the one file that task touches outside the generated set. Status per code (`server.StatusFor`): `validation` 400, `unauthenticated` 401, `forbidden` 403, `not_registered` 403, `not_found` 404, `conflict` 409, `replaced` 409, `session_lapsed` 410, `session_closed` 410, `rate_limited` 429, `unavailable` 503, `internal` 500; the validator's own statuses map 400 and 422 to `validation`, 401 to `unauthenticated`, 404 to `not_found` (its router reports an unknown path and a wrong method on a known path both as 404, the latter with the text "method not allowed"; probed on 2026-10-21 with nethttp-middleware v1.2.0), anything else to `internal` (413 is written by the body-limit middleware of choice 11, never by the validator, so `validatorCode` never sees it). An empty path parameter (`DELETE /v1/sessions/`, `PUT /v1/channels//subscription`) is a router 404 `not_found` on the wire, the code the core gives a lookup by a name no row has, so the two transports agree without any client-side guard; a name containing `/` travels percent-encoded as one segment and is judged by the core (choice 17). `Problem.type` is `urn:agentbus2:problem:<code>` (a URN, because no domain is claimed and RFC 9457 requires only a URI reference), `title` is `http.StatusText(status)`, `detail` the `bus.Error.Message` (already bounded to 1024 bytes by Milestone 3), `instance` the request path.
4. **One error path.** Handlers return `nil, err` for every failure and the strict server's `ResponseErrorHandlerFunc` writes the problem through `server.ProblemFor(err)` (a `*bus.Error` by its code, `context.Canceled` and `DeadlineExceeded` as 499-style silence: the client is gone, nothing is written, any other error `internal`). The generated typed `default` response objects are not used by handlers: with every status decided by the code, one hook is the whole mapping and no handler can forget it. The spike routed only unexpected errors this way; here it is every error, which is why Task 2's hook test asserts a `*bus.Error{conflict}` returned by a handler reaches the client as a typed 409.
5. **Authentication seam.** `server.Authenticator` is `Authenticate(r *http.Request) (identity string, err error)`; the auth middleware attaches what it returns to the request context under the `identity` key, always, even when it is `""`, and never refuses by itself. The document's security requirements are enforced by the validator's `AuthenticationFunc`, which succeeds exactly when `IdentityFrom(ctx)` is non-empty, so which operations need one is stated once, in the document (`security: []` on the three discovery operations), not in Go. `server.RefuseAll` (the default and the only authenticator `agentbus2 server` constructs until Milestone 5) returns `""`, so every protected operation is 401 `unauthenticated`. `server.InProcess` returns the value of a second, unexported context key, `inprocIdentity`, which only `server.InProcessTransport(h, identity)` sets: a context value never crosses a socket, so a network request cannot carry it, and because the middleware writes the `identity` key unconditionally, a `RefuseAll` server behind the in-process transport still sees `""` (the transport's key is invisible to `IdentityFrom`). This is the local mode of Decisions 35 and 36 (identity is the registered name; the client is in the same process), not a test hook; Milestone 6 wires it for the local profile and Milestone 5 adds the bearer authenticator beside it.
6. **The validator middleware is adopted** (`nethttp-middleware` with `ErrorHandlerWithOpts` writing problems) over the document embedded by a second generator config into `internal/gen/spec` (`embedded-spec: true` and nothing else; package `spec`, `spec.GetSwagger()`), imported by `internal/server` only. Rationale: ADR 0007 lists the validator as the recommended auth path for oapi-codegen v2.8.0, the exit criterion names it, and it makes unknown routes and methods problem+json without a hand-written router fallback (its router answers an unknown path and a wrong method, both as 404, before the `ServeMux` would). ADR 0007 counted the embedded document as the main footprint cost (5 non-standard packages without it, 24 with); keeping it out of `internal/gen` means `internal/bus/remote`, and so Milestone 6's MCP server and CLI, never link kin-openapi or the gzip'd document (Task 11 records the measured `go list -deps ./internal/bus/remote | wc -l` in the ADR 0007 addendum). The `openapi3.T` is loaded once per process (`sync.Once` over `spec.GetSwagger()`), with `Servers` cleared so any host matches.
7. **Discovery is computed from the embedded document** (Decision 65 by construction): `auth_methods` is one entry per `components.securitySchemes` entry, `{name, type, scheme?, bearer_format?, openid_configuration?}`, with the `openIdConnect` entry's URL resolved against the request (`<scheme>://<host>/.well-known/openid-configuration`, scheme `https` when `r.TLS != nil` else `http`); `openid_configuration` repeats that URL; `issuers` is the configured external issuers, `[]` until Milestone 5. `api_versions` is `["v1"]`, `server_version` is `version.Version`, `capabilities` is computed from what is available: `long_poll` always, `semantic_search` when `core.Embedder() != nil`; `pgvector` and `websocket` are never present in this milestone. `/.well-known/openid-configuration` returns `{issuer: <scheme>://<host>, token_endpoint: <issuer>/v1/auth/token, jwks_uri: <issuer>/v1/auth/jwks, token_endpoint_auth_methods_supported: ["private_key_jwt"], token_endpoint_auth_signing_alg_values_supported: ["EdDSA", "ES256"]}` (Decisions 55, 70, 84, 91). The document's `openIdConnectUrl` is the server-relative `/.well-known/openid-configuration` (probed: kin-openapi loads and validates it).
8. **The auth operations are not declared in this milestone's document.** `POST /v1/auth/token`, `GET /v1/auth/jwks` and registration arrive with their schemas in Milestone 5, as do admin reset and reset-credential (choice 1). Rationale: a declared operation needs a strict handler, and a handler that can only say "not yet" would need a status and a code the design does not have (a 503 `unavailable` would tell clients to retry). The `openid-configuration` document names the two paths now so Decision 91's URL is stable; until Milestone 5 they answer 404 `not_found`, stated in pending item 2.
9. **Watch parameters on the wire.** `after` is an optional `int64` defaulting to 0 (the floor rule of Decision 42 with no floor); `timeout` is an optional `number` (`format: double`, generated as `*float64`) of seconds, fractional allowed (`0` and absent mean `WatchMaxSeconds`; above the cap is clamped by the core; negative is `validation`); `include_own` is an optional boolean defaulting to `false` (Decision 45). Rationale for a fractional `timeout`: the Milestone 3 suite watches with sub-second timeouts and asserts that `-1 ns` is `validation`, and an integer-seconds parameter would turn both into 0, which means the cap.
10. **`receive` is a POST** with its body (it writes the pending token and cursors) and no `Idempotency-Key` (Milestone 3 pending item 12, recommendation A, which this plan proceeds on; it is idempotent by construction).
11. **Body limit.** The outermost middleware (`limitBody`, before auth and the validator) reads every request body itself with `io.ReadAll(io.LimitReader(r.Body, limit+1))` when `r.Body` is neither nil nor `http.NoBody`, with the limit `core.Cfg.MaxMessageKiB * 1024 + 1 MiB` (the largest legitimate body is a send near the envelope bound plus metadata and tags); more than `limit` bytes is 413 with code `validation` through `WriteProblem` and nothing further runs; otherwise it replaces `r.Body` with a `bytes.Reader` over what it read and sets `r.ContentLength` to that length, so the validator and the handlers only ever see a bounded, replayable body. It never consults `r.ContentLength` before reading (a chunked body reports `-1`) and never uses `http.MaxBytesReader`: the validator reads a protected operation's body during security validation and rewrites every `*openapi3filter.RequestError` as a flat `errors.New`, so a `*http.MaxBytesError` would surface there as a 401 or a 400 and never reach `errors.As` (Evidence). The read-ahead holds at most `limit+1` bytes per in-flight request, which a local bus accepts.
12. **Suite transport switch.** `internal/conformance/bus` reads `AGENTBUS2_BUS_TRANSPORT` once in `TestMain`: `""` or `local` keeps Milestone 3's `local.New`; `inproc` builds, per harness, one `server.New(h.core, server.Options{Auth: server.InProcess{}})` and, per `newBus` call, a `remote.New` over `gen.NewClientWithResponses("http://inproc", gen.WithHTTPClient(&http.Client{Transport: server.InProcessTransport(handler, identity)}))`; any other value fails every test with the two accepted values named (`AGENTBUS2_BUS_TRANSPORT must be local or inproc`), which check 6 of `scripts/check-gates.sh` re-runs on every `make verify`. `make test-conformance` runs the `bus` package twice, once per value. Rationale: Milestone 3's `var newBus` exists for this; a subtest layer would rename every test and break `scripts/m3-exit-counts.sh` and the `TestScaffold/postgres` greps in `scripts/check-gates.sh`, while an environment variable keeps every name and log shape. The negative half (that the `inproc` run really crosses the wire) is Task 4's `TestTransportInUse` and Task 11's self-test block 11.
13. **Remote error mapping** (spec 3.3 "never by guessing"). A problem+json body with a known code becomes `&bus.Error{Code, Message: detail (title when detail is empty), Retryable}` by struct literal (never `bus.Errorf`, which panics on an unknown code); an unknown code is preserved as received with the wire's `retryable`, so `bus.CodeOf` returns it and no caller mistakes it for a known one. A non-2xx response without a parsable problem (a proxy's HTML 502) is `{unavailable, "HTTP <status>", true}` for 5xx and `{internal, "HTTP <status>: <first 200 bytes>", false}` otherwise. A transport error returns `ctx.Err()` when the context is done and `{unavailable, err.Error(), true}` otherwise. `watch` 204 is `WatchResult{Woke: false}`; `watch` 409 goes through the problem path and is `replaced`.
14. **Server command flags.** `agentbus2 server -listen <host:port> (-sqlite <path> | -postgres <dsn>)`: `-listen` required (no default port is decided anywhere; port `0` is accepted and the bound address is printed), exactly one store flag required, an actionable message names the missing or conflicting flags. Decision 85's configuration file and `AGENTBUS2_SERVER_*` variables are Milestone 5, which replaces this flag set (pending item 3). The notifier is `notify.NewMemory()` (Decision 52: SQLite server and, until Milestone 7's `NOTIFY`, Postgres); two `agentbus2 server` processes over one SQLite file are therefore unsupported (each would miss the other's hints; a watch would still end at its timeout), and the local multi-process mode of Decision 68 is the Milestone 6 client with `notify.NewPolling`, which Task 10 exercises through `cmd.Serve`. At start, in order: open the store (Decision 34's rules and migrations), `core.New` with `core.Defaults()`, `channels.Service.EnsureGeneral` (Milestone 3 Task 4 names this milestone's server as its caller), the maintenance loop (`maintenance.Service.Tick` every `MaintenanceIntervalSeconds`, stopped on shutdown), then listen. No embedder (its endpoint is Milestone 5 configuration, Decision 85).
15. **`http.Server` settings** for the long-poll: `ReadHeaderTimeout` 10 s, `ReadTimeout` 30 s, `WriteTimeout` 0 (the watch handler's own deadline bounds it), `IdleTimeout` 120 s, graceful `Shutdown` with a 60 s context so armed watches finish (spike need 1: a handler blocked on `r.Context()` sees the client go). `ReadTimeout` does not bound the handler: it is a deadline on reading the request (headers and body) and, for a bodiless GET, on the connection's background read, whose expiry does not cancel `r.Context()` or close the connection while the handler runs; a reviewer's probe on go1.27.2 (an `http.Server{ReadTimeout: 1s}` with a handler blocking 3 s on a bodiless GET: the handler's context survived and the client got 204) is the observation, and Task 10's `TestWatchLongPollSurvivesReadTimeout` over a real socket is the evidence this plan relies on, because the spike's proof of need 1 came from `httptest.Server`, which sets no timeouts. `cmd.Config.ReadTimeout` exists so that test can shorten it.
16. **Package layout.** `internal/server` (handler construction, problems, auth seam, in-process transport, discovery, one handler file per aggregate), `internal/server/cmd` (the command: `Run`, `Serve`), `internal/bus/remote` (the remote `Bus`), the suite's `transport_test.go`. `internal/bus/remote` has no knowledge of `internal/server`: the local mode wiring (handler plus transport plus client) is the caller's (Milestone 6's profile code, the suite here).
17. **Path parameters on the wire** (Decision 93's `NameRule` allows 1-128 UTF-8 bytes with only `/` and control characters banned, so a space, `%`, `?`, `#`, `+` and non-ASCII are legal channel names and travel as a path segment on ten operations). The rule, stated in `info.description` of the document and in `internal/gen/doc.go`: the client percent-encodes every path parameter once (`url.PathEscape` in the runtime's path styling: a space is `%20`, `%` is `%25`, `?` is `%3F`, `#` is `%23`, `,` is `%2C`, `*` is `%2A`, `+` and `:` travel as themselves, non-ASCII is UTF-8 percent-encoded); the server decodes once, in Go 1.22 `ServeMux`, which matches wildcards against the escaped path (so `%2F` is one segment) and hands `r.PathValue` decoded; the generated binder takes that value as already unescaped (`ValueIsUnescaped: true`, verified in the v2.8.0 std-http template), so nothing double-decodes and `100%` or `a%2Fb` as a literal name round-trips. Hand-written code never calls `url.PathUnescape` on a bound parameter and never builds a path by string concatenation (the remote `Bus` only ever calls the generated client). The validator's router matches the escaped path as well (kin-openapi's gorillamux router is built with `UseEncodedPath()`; probed: `a%2Fb` reached the handler as `a/b`), so a `/` inside a name travels as one segment and is judged by the core, which answers `not_found` for a name no channel has, as it does locally. The one shape no router matches is the empty segment (`/v1/channels//subscription`, `DELETE /v1/sessions/`): 404 `not_found` from the validator's router, the code the core gives the empty name too (a lookup by `""` finds no row), so the remote `Bus` has no guard and sends what the generated client builds (Decision 80: the rules stay in the core). The in-process transport hands the client's `*http.Request` to `ServeHTTP` without serializing the request line, so the real-socket parse of an odd name is covered separately (Task 10's `TestOddChannelNameOverTCP`). Rationale: the Milestone 3 suite uses only plain names, so without these tests a local/remote divergence on legal names would pass the exit criterion silently.
