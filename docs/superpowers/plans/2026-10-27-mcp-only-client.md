# MCP-only Client Implementation Plan (Eric's decisions of 2026-10-27, issue #12)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A second binary, `agentbus2-mcponly` (`cmd/agentbus2-mcponly`), whose only job is to connect an agent to an agentbus2 server over stdio MCP: commands `serve`, `register`, `check`, `config`, `help [topic]`, `version`; flags `-server`, `-identity`, `-credential`, `-enrollment-token[-file]`, `-algorithm`; guided help whose every example is executed against a real server; packaged as five more release archives with its own Homebrew, Scoop and winget packages.

**Architecture:** Local (SQLite) mode moves out of `internal/client` into `internal/client/localmode`, injected through a new `client.Options.Local` opener that only the full binary passes, so the new main links no core, server, Store engine, kin-openapi or TUI (measured: 11.0 MB and 13 modules against 27.0 MB and 53, linux/amd64 stripped). The command code is `internal/mcpcli` over `internal/client` (gaining `-server`/`-credential` resolution, the registration logic lifted from `internal/cli`, and an unauthenticated discover/health probe) and `internal/mcpserver` (gaining an `Edition` that selects the agent-facing text). A new `scripts/m10-exit-checks.sh` proves the dependency set inside `make verify`.

**Tech Stack:** Go 1.27 (`CGO_ENABLED=0`), the MCP Go SDK (stdio), oapi-codegen client (`internal/gen`, unchanged), bash release tooling (`release/`), GitHub Actions, PowerShell 5.1/7 for `install.ps1`.

**Spec:** `docs/superpowers/specs/2026-10-27-mcp-only-client-design.md` (all six decisions are Eric's of 2026-10-27; decision 4 renamed the binary to `agentbus2-mcponly`). The sidecar brief `2026-10-27-mcp-sidecar-design.md` (#21) is postponed and out of scope.

**Eric's decisions this plan implements** (recorded by Task 9 in ADR 0015):
1. Build: A. `cmd/agentbus2-mcponly` plus local mode moved out of `internal/client`; no build tags.
2. State: A. The flags map onto today's profiles and files; `-credential FILE` may read a key from any path (0600 on Unix, owner-only on Windows, never from the repository file).
3. Packaging: B. Separate `agentbus2-mcponly-vX.Y.Z-<platform>` archives (fourteen assets), Homebrew formula `agentbus2-mcponly`, Scoop `bucket/agentbus2-mcponly.json`, winget `ericfitz.agentbus2-mcponly`; `install.sh --mcp-only`, `install.ps1 -McpOnly`.
4. Name: `agentbus2-mcponly`. The MCP server's implementation name stays `agentbus2`, so tool names do not change.
5. Waking: A. `receive` with `wait_seconds`, documented in the help and the MCP-only `Instructions`.
6. No command: help on stderr, exit 2.

## Settled open notes

Each is the agent's choice where the brief left one open; each carries `open note: mcp-only-client N` (Go `//`, shell `#`, Markdown `<!-- -->`) in the named file, so `rg -n 'open note: mcp-only-client' .` finds every one.

1. **Opener shape.** `client.Options.Local client.LocalOpener` (a func); `localmode.Open` / `localmode.Opener(localmode.Options{Config})`; `client.Conn.Local any` read by `localmode.Core(c)`. Only `Options.Config` and `Conn.Core` leave `client`; `Notifier` (`internal/core/notify`, a leaf), `PollInterval`, `Maintenance`, `OpenLogger` stay as plain fields read by the opener. Rationale: the gate forbids exactly what links the core, with the least test churn. Marker: `internal/client/options.go`.
2. **Command package.** `internal/mcpcli` holds every command; `cmd/agentbus2-mcponly/main.go` is the signal context and `os.Exit` only. Rationale: vetted, linted and unit-tested like `internal/cli`. Marker: `internal/mcpcli/doc.go`.
3. **`-server` on an undefined profile.** `serve`, `check` and `config` use an in-memory server profile and write nothing; only `register` creates the profile in `config.json` (as `register -server` does today). Rationale: a read-only command never edits config. Marker: `TestResolveServerFlag`.
4. **`-credential` is read-only.** `register -credential FILE` registers that key's public half and writes neither a credential file nor a pending file; `config.json` never records the path (so `config` prints `-credential FILE` in `args`); it is a ResolveError with a `credential_process` profile, a local profile or a human sign-in. Rationale: a mounted secret is owned by its mount. Marker: `TestResolveCredentialFlag`.
5. **Windows owner-only read check.** `fileacl.CheckOwnerOnly` refuses a NULL DACL and any access-allowed entry for a SID other than the current user, LocalSystem (`S-1-5-18`) and BUILTIN\Administrators (`S-1-5-32-544`); it runs for `-credential` files only. Rationale: those two SIDs are Windows' root, which reads a 0600 file on Unix too; files the Store writes are owner-only by construction and Windows CI tests write keys with `os.WriteFile`. Marker: `internal/fileacl/acl_windows_test.go`.
6. **Decision 16 applies to `serve`.** The OS-login guard moves to `mcpserver.IdentityGuard` and both binaries call it; the message names the command (`agentbus2 mcp` or `agentbus2-mcponly serve`). Rationale: one rule for every agent MCP server. Marker: `internal/mcpserver/guard_test.go`.
7. **Tool schemas are shared.** Both editions serve the same 25 tools with the same descriptions (the `wait_seconds` description keeps its sentence on `agentbus2 wait`, which says what it replaces, not what to run); only `Instructions` and the `init` prompt differ by edition. Rationale: one schema set, and the tool count gate stays 25. Marker: `TestInstructionsByEdition`.
8. **`check` without an identity** runs `reach` and `health`, prints `next: agentbus2-mcponly register -server URL -identity NAME`, exit 0; with one it runs all six steps and stops at the first `FAIL`, exit 1. Rationale: step 1 of the help is exactly that call. Marker: `TestCheckSteps`.
9. **Gates.** `scripts/m10-exit-checks.sh --deps-only` runs inside `make verify` (Docker-free, seconds), unlike the m4 to m8 `--deps-only` runs, which stay in the `gates-selftest` job; the e2e additions are new tests (`TestMCPOnly`, `TestHelpExamples`) counted by m10, so the m6 counts (13 steps, 11 cells) and `check-gates-selftest.sh` block 23's lists do not change. Marker: `scripts/m10-exit-checks.sh`.
10. **Installers.** `--mcp-only` and `-McpOnly` stay flags (decision 3); the piped forms are `curl -fsSL …/install.sh | sh -s -- --mcp-only` and `& ([scriptblock]::Create((irm …/install.ps1))) -McpOnly`. Both binaries install into the same directory (`~/.local/bin`, `%LocalAppData%\Programs\agentbus2`); the `.old-*` sweep is per binary name. Rationale: one PATH entry. Markers: `install.sh`, `install.ps1`.
11. **Second Windows README.** `release/windows-zip-README-mcponly.txt` for the second zip. Rationale: the current one tells the reader to run `agentbus2 init`. Marker: the comment on `package-windows`'s sparse checkout in `release-build.yml` (a README is shipped text, so it carries none).
12. **Help example format.** Example lines are `  $ agentbus2-mcponly …`, expected output lines `    > …` (a `<…>` token matches any non-empty text), an expected non-zero exit `    (exit N)`; placeholders `https://agentbus.example.com`, `my-agent`, `./enrollment-token`, `./agent-key.pem`. Rationale: one grammar the e2e test parses. Marker: `internal/mcpcli/help.go`.
13. **Enrollment token sources.** Precedence: `-enrollment-token`, `-enrollment-token-file`, `AGENTBUS2_ENROLLMENT_TOKEN`; both flags at once is exit 2; the file is trimmed of surrounding white space and must be a regular file, non-empty, at most 4 KiB; the token never appears in any output or log. Marker: `TestEnrollmentTokenSources`.
14. **Scope.** The brief's "Out of scope (proposed)" list is adopted: no local mode, no `login -human`, no TUI, no hooks, no `wait`/`watch`/`park`, no server change, no #13. `TestOnlyMCPCommands` pins the command set. Marker there.

**Agent choices that are one constant each** (no marker): `check` step names `reach`, `health`, `identity`, `credential`, `token`, `access`; `-credential` and `-enrollment-token-file` relative paths are made absolute at parse time; the `config` JSON server key is `agentbus2`.

## Review Focus

1. The full binary's built-in local `default` profile on the same machine: `agentbus2-mcponly check` and `config` with no `-server` exit 2 with `this binary has no local mode`, and `serve`'s tools answer `validation` with that text; neither ever opens a SQLite file. Pinned by `TestOpenLocalWithoutOpener` (Task 1) and e2e `9-no-local-mode` (Task 5).
2. An enrollment token never reaches stdout, stderr or the MCP log, on success and on every refusal (`forbidden` without a token, a wrong token, an unreachable server): `TestRegisterTokenNeverEchoed` (Task 4) greps both streams for the token.
3. A Kubernetes-style secret mount: a symlink to a regular file at 0400 is accepted by `-credential`; the same at 0644 is refused naming the path and `chmod 600`, and `check` prints `fix: chmod 600 FILE`: `TestLoadFileFollowsSymlinkAndChecksMode` (Task 3), `TestCheckCredentialModeFix` (Task 5).
4. Upgrading on Windows while `agentbus2-mcponly serve` runs: `install.ps1 -McpOnly` renames the running `agentbus2-mcponly.exe` aside, and its `.old-*` sweep never touches `agentbus2.exe` or `agentbus2.exe.old-*` in the same directory: `test-install.ps1` case `mcponly-upgrade-beside-full` (Task 8).
5. `AGENTBUS2_SERVER` in the server's own environment changes nothing (the server reads only `AGENTBUS2_SERVER_` plus a name): `TestLoadIgnoresClientServerVariable` (Task 4).
