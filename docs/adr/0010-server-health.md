# ADR 0010: Server health

Status: Accepted (agent proposal 2026-10-25; Eric reviewed every decision and ratified decisions 1 to 11 on 2026-10-25, and ruled on decision 12 himself)

Covers issue #11. The design is `docs/superpowers/specs/2026-10-25-health-design.md`; the operator guide is `docs/ops/health.md`. Decisions 1 to 11 were proposed by the agent working overnight and each is labeled "agent proposal 2026-10-25, ratified by Eric 2026-10-25"; decision 12 is Eric's own ruling. Each lists the files that reversing it would touch. No earlier decision made by Eric is changed except as decision 12 states: where the issue seemed to need one, the option that leaves the existing decision intact was taken.

## Context

Issue #11 asks for server health through the REST API, surfaced in the TUI health overlay and in an MCP tool: version, store engine and reachability, schema version, maintenance-lock holder and last run, embedding backlog and status, storage and capacity notices, with access rules consistent with Decision 73. Before this ADR the only probe was the unauthenticated `GET /v1/discover` (Decision 43), which never touches the store, and the only richer views were the admin-only `Status` and `Usage` operations.

## Decisions (agent proposals 2026-10-25, ratified by Eric 2026-10-25)

1. **One operation with optional security and a tiered body.** Agent proposal 2026-10-25, ratified by Eric 2026-10-25. `GET /v1/health` declares `security: [{}, {bearerAuth: []}]`, so the validator never answers 401 and the handler picks the tier (health is counted as an open operation: decision 12) from the caller's identity. Alternatives: two operations (an unauthenticated `/v1/healthz` and a bearer-only `/v1/health/detail`), rejected as double the wire surface for one document; a bearer-only operation, rejected because it cannot serve a load-balancer probe. To reverse: `api/openapi.yaml`, `internal/gen`, `internal/gen/spec` (`make generate`), `internal/server/health.go`, `internal/server/convert.go`, `internal/bus/remote/health.go`, the operation tables in `internal/server/cmd/cmd_test.go` and ADR 0001's operation count.
2. **A presented but invalid bearer is 401, not the probe tier.** Agent proposal 2026-10-25, ratified by Eric 2026-10-25. Every other open operation ignores a bad bearer; health, the one exception to that rule (decision 12), answers `unauthenticated`, so a client with a stale token sees the failure (and the transport's one-shot refresh on 401 keeps working) instead of a quietly smaller document. Alternative: treat it as anonymous, as discover does; rejected because a monitoring client would read "fewer fields" as "healthy". To reverse: `internal/server/health.go`, `internal/server/health_test.go`, the comment in `internal/server/cmd/cmd_test.go`, the sentence in `docs/ops/deploy.md` section 5 and `docs/ops/health.md`.
3. **The document is 200-only; an unreachable store is a 503 problem.** Agent proposal 2026-10-25, ratified by Eric 2026-10-25. Decision 46 makes every error `application/problem+json`; a 503 carrying the document would be the first non-problem error body. The TUI shows the problem's message instead. Alternative: a 503 with `status: unavailable` in the `Health` schema. To reverse: `api/openapi.yaml`, `internal/core/health/health.go`, `internal/server/health.go`, `internal/bus/remote/health.go`, `internal/tui/health.go`.
4. **Liveness is `GET /v1/discover`; readiness is `GET /v1/health`.** Agent proposal 2026-10-25, ratified by Eric 2026-10-25. A liveness probe on discover never restarts a replica for a database outage; a readiness probe on health takes a replica out of rotation only while it cannot serve. Alternatives: one endpoint for both, rejected because a liveness probe on it would restart pods for a Postgres outage; a dedicated liveness endpoint (`GET /v1` or `GET /v1/livez`), which Eric considered on 2026-10-25 and rejected, choosing to keep liveness on `GET /v1/discover` (it is already unauthenticated, store-free and always 200 while the process serves). To reverse: `docs/ops/deploy.md` section 5, `docs/ops/health.md`.
5. **`health` is a new discover capability.** Agent proposal 2026-10-25, ratified by Eric 2026-10-25. Decision 43 says additions get a capability; `Capabilities` always returns `health`, sorted with the others. To reverse: `internal/server/discovery.go`, `internal/server/discovery_test.go`, the discover schema in `api/openapi.yaml`.
6. **The maintenance block is this process's view, from an in-memory record, with no schema change.** Agent proposal 2026-10-25, ratified by Eric 2026-10-25. `Store.Locks.TryLock` reports only whether this owner holds the lock, and a Postgres advisory lock has no readable owner. Options: (A) schema version 7 with a `maintenance_runs` row written by every tick; (B) the record in the `notices` table under a reserved kind; (C) an in-memory record on `core.Core` written by `maintenance.Tick`. C was taken: no schema or contract change, exact for one server over SQLite, and on Postgres a probe of each replica shows which one answers `held`. Option A is the one Eric is most likely to prefer if cross-replica history is wanted; the record type can be filled from a Store row later without changing the wire shape. To reverse: `internal/core/maintenance_record.go`, `internal/core/core.go`, `internal/core/maintenance/service.go`, `internal/core/health/health.go`, and for A a migration in `internal/store/sqlstore`, the schema-version sentences in `CLAUDE.md` and `docs/ops/upgrade.md`.
7. **The probe tier sees the true `status`, `degraded` included.** Agent proposal 2026-10-25, ratified by Eric 2026-10-25. It reveals that something is off, not what. Alternative: collapse `degraded` to `ok` for anonymous callers, rejected because a load-balancer dashboard that can show amber is the point of the probe. To reverse: `internal/core/health/health.go` and its tests, `docs/ops/health.md`.
8. **The identity tier includes `store.engine`, `store.schema_version`, `started_at` and the embedding state and counts.** Agent proposal 2026-10-25, ratified by Eric 2026-10-25. An agent diagnosing "search returns text only" needs the embedding state; the engine and schema are not secrets from an identity that holds a key to the server. Alternative: all of them admin-only. To reverse: the tier checks in `internal/core/health/health.go`, the `Health` schema descriptions in `api/openapi.yaml`, `internal/mcpserver/server.go`, `internal/tui/health.go` and the table in `docs/ops/health.md`.
9. **A sixth consumer interface, `Monitoring`, embedded in `Bus`, rather than a method on `Admin`.** Agent proposal 2026-10-25, ratified by Eric 2026-10-25. Decision 7 splits `Bus` by consumer; `Admin` is the administrator seam (Decision 48) and health is for every caller. Alternative: add `Health` to `Admin`, rejected because it would say the wrong thing about who may call it. To reverse: `internal/bus/health.go`, `internal/bus/bus.go`, `internal/bus/doc.go`, `internal/bus/local/health.go`, `internal/bus/remote/health.go`, and every `Bus` fake in the tests.
10. **`agentbus2 health [-profile P] [-identity I]` ships as an optional last task.** Agent proposal 2026-10-25, ratified by Eric 2026-10-25. It prints the document as one JSON object and exits 0 for `ok` or `degraded`, 1 for a `bus.Error`, 2 for a flag or resolution error. It is not in the issue's acceptance criteria. Alternative: no CLI command (operators `curl` the endpoint or run `agentbus2 status`). Also rejected for now: a Dockerfile `HEALTHCHECK` with a server probe subcommand, because the image has no shell and nothing in the compose file depends on replica health. To reverse: `internal/cli/health.go`, its test, the `health` entry in the command table in `internal/cli/cli.go`, and `CLAUDE.md`.

## Later decisions (decision 11: agent proposal, ratified by Eric 2026-10-25; decision 12: Eric)

11. **The 503 carries a fixed `store unreachable` message; the cause is logged.** Agent proposal 2026-10-25, ratified by Eric 2026-10-25. The probe tier is unauthenticated, and a driver error names the Postgres host, user and database or the SQLite file path, so the wire text is fixed and the cause goes to the server log. Any `*bus.Error` from the store path other than `not_registered` and `forbidden` is also mapped to `unavailable`. Alternative: a bounded driver text (the first version, `store unreachable: <text>`), rejected as an information leak to unauthenticated callers. To reverse: `internal/core/health/health.go` (`unavailable`) and the tests that assert the body does not contain the host, user or path (`internal/core/health/health_test.go`, `internal/server/health_test.go`).
12. **`GET /v1/health` is counted as an open operation: 8 open, 44 protected, 52 in all.** Decision by Eric, 2026-10-25 ("Count as open"). The `health` operation has no separate "optional" category. The rule that an open operation never answers 401 is relaxed: health is the one open operation that answers 401, to a presented invalid bearer (decision 2); with no bearer it is 200. `internal/gen/openapi31_test.go` pins 8 open and 44 protected and checks that health's security is exactly `[{}, {bearerAuth: []}]`, so the exception stays pinned; `TestRunRefusesEveryProtectedOperation` in `internal/server/cmd/cmd_test.go` counts 44 protected and 8 open, with a named exception for health (a bad bearer is 401, no bearer is 200); ADR 0001's addendum states 52 (44 and 8). Alternative, rejected by Eric: a separate "optional" category (7 open, 44 protected, 1 optional), the agent's first reading. To reverse: `internal/server/cmd/cmd_test.go`, `internal/gen/openapi31_test.go` and the addendum in `docs/adr/0001-transport-and-api.md`.

## Consequences

- `Store.SchemaVersion` joins the Store contract (ADR 0004, Health addendum); the maintenance record adds nothing to it.
- The MCP server has 25 tools; the `health` tool unparks a parked session like every tool but `receive` (Decision 18).
- Not done on purpose: a cross-replica maintenance record, a Docker `HEALTHCHECK`, metrics.
