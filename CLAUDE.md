# CLAUDE.md

agentbus2: a Go CLI, local stdio MCP server and API server for coordinating agents. It is a breaking redesign of agentbus v1 (`/Users/efitz/Projects/agentbus`), installed side by side with it under separate names and paths (see README.md and docs/).

## Commands

- Build: `make build` (`CGO_ENABLED=0`; SQLite is `modernc.org/sqlite`, Postgres is `pgx`).
- Tests: `make test`; `make test-race` for the race detector.
- Lint: `make lint` (golangci-lint v2), `make vet`, `make fmt-check`.
- Done gate: `make verify` (build, vet, gofmt, lint, `tidy-check`, `generate-check`, unit tests, the Store and Bus conformance suites against both SQLite and Postgres, and `check-gates`; `release-check` is not part of it and runs as its own CI job). Postgres for the suites comes from testcontainers unless `AGENTBUS2_TEST_POSTGRES_DSN` names a reachable server (an empty value counts as unset). `make verify` needs Docker either way, because `check-gates` runs the suite binaries in a `busybox` container to prove the no-Docker path. A run that skips the Postgres suites is not a pass. Work is done only when `ci.yml` and `windows.yml` are green on the pushed commit (including the `release-check` job); a red `windows.yml` is fixed first.
- `make test` is Docker-free (every package except `internal/conformance`); `make test-conformance` runs the suites only.
- `make generate` regenerates `internal/gen` and `internal/gen/spec` from `api/openapi.yaml`.
- `make test-conformance` runs the bus suite twice: `go test ./internal/conformance/...` (the `local` transport), then the `bus` package with `AGENTBUS2_BUS_TRANSPORT=inproc` (the remote `Bus` over the generated client and the in-process transport). Any other value fails the suite.
- Run the server: `agentbus2 server [-config FILE] [-listen host:port|unix:PATH] [-registration open|enrollment] (-sqlite <path> | -postgres <dsn>) [-set name=value]...`; settings come from the file, then `AGENTBUS2_SERVER_<NAME>`, then the flags (`internal/server/config`, `config.Settings()` lists them). The registration default is `open` on a loopback or unix listener and `enrollment` on any other.
- Host commands (no listener, no credential): `agentbus2 server admin [-config|-sqlite|-postgres|-set] users|admins add|remove|list | reset-credential NAME | create-identity NAME [-scope S] | create-human EMAIL | enrollment create|list|revoke`.
- Client commands (`internal/cli`; every one takes `-profile P` and `-identity I` unless noted; a result is one JSON document on stdout, a `bus.Error` is `agentbus2: <code>: <message>` and exit 1, a flag or resolution error exit 2):
  - `init [-global] [-harness claude|codex|grok] [-dry-run] [-profile P] [-identity I]` (here `-profile` and `-identity` name the new repository profile) registers the MCP server, hooks and skill with the harnesses; in a repository it writes `.local/agentbus2.json`. The new profile's identity defaults to the repository name, or `<user>-home` for a repository rooted at the home directory (Decision 15).
  - `register [-server URL] [-enrollment-token T] [-algorithm EdDSA|ES256]` creates the key and registers it; `login` exchanges and caches a bearer (server profiles only); `login -human` (needs the profile's `oidc`, refuses `-identity`) always runs the browser sign-in and prints `logged in as <identity> at <server> (token expires <RFC 3339>)`.
  - `mcp` is the stdio MCP server (refuses, exit 1, when its identity is the OS login name: Decision 16; 25 tools; nothing on stdout but the protocol; log in `<data dir>/logs/mcp-<pid>.log`).
  - `watch` and `wait [-timeout D]` take `[-session ID] [-include-own] [-no-harness-watch]`; `watch` prints one line per wake and never exits 0 or 1, and is deprecated: the idle wake on every harness except Codex is a background `agentbus2 wait` (Bash `run_in_background`; exit 0 receive and start again, 3 or 4 nothing, 2 report; Codex has none: Decision 17). Exit codes (spec 3.5): 0 woke (`wait` only), 1 timeout (`wait` only), 2 error, 3 replaced or signaled (SIGINT, SIGTERM, SIGHUP), 4 harness gone.
  - `park` / `unpark [-session ID]` (decision 18): `park` sets `parked` in the session state file, so `wait`, `watch` and the Stop hook stay silent until an unpark (`park` exits 2 with no session). `unpark` is a hook like `stop-hook` (prints nothing, always exits 0) that `init -global` installs as `UserPromptSubmit` for Claude Code, Codex and Grok; the MCP `register` (a hinted one too) and every MCP tool but `receive` also unpark every parked state file of the server's harness. `park`/`unpark` without `-session` act on the harness's primary session. Writes to a state file take the short `sessions/.state.lock`. No message wakes a parked session (no DMs).
  - `session-start-hook` (Claude Code and Codex `SessionStart`; Grok ignores its stdout and gets the rule file instead) prints the register steps as plain text, nothing when the profile or identity does not resolve or the identity is the OS login name; the MCP server's `Instructions` carry the same steps (`mcpserver.RegisterSteps`).
  - `stop-hook`, `subagent-hook` and `session-start-hook` read the harness's JSON on stdin, take no flags, always exit 0 and fall open within 500 ms, leaving a line in `<data dir>/logs/hook.log`.
  - `session open [-hint H] [-resume-token T] [-cursor CH=SEQ]...` and `session close ID`; `channels list|create [-scope S]|delete|rename|acl|subscribe|unsubscribe|tags`; admin: `scopes create|list|get|done -retire with_bridge|normal`, `identities create [-scope S] NAME`, `bridges create [-slack-name N]|list|get|remove` (`unavailable`, not retryable, where no bridge is wired); `send [-subject S] [-type T] [-tag T]... [-reply-to SEQ] [-metadata K=V]... [-session ID] [-key K] CHANNEL [CONTENT|-]`; `receive [-session ID] [-ack B] [-count N] [-channel C]... [-include-own] [-no-ack]`; `history`, `search`, `memories get|edit|delete|revisions`, `tasks create|list|get|update|claim|release`, `health` (the health document as your tier sees it, one JSON document; no flags beyond `-profile` and `-identity`), `status`; flags go before positional arguments.
  - `tui` is the terminal UI over the Bus (see `docs/tui.md`): `agentbus2 tui [-profile P] [-identity I]`, no other flag; on a local profile with no identity chosen it falls back to the OS login name (`internal/cli/osuser.go`); on a server profile it is the human who signs in through the profile's `oidc` provider (Decision 11; `-identity` is exit 2); it runs the maintenance loop in local mode.
  - `version` and `help`. Environment: `AGENTBUS2_PROFILE`, `AGENTBUS2_IDENTITY`, `AGENTBUS2_CONFIG_DIR` (else `$XDG_CONFIG_HOME/agentbus2`, `~/.config/agentbus2`), `AGENTBUS2_DATA_DIR` (else `$XDG_DATA_HOME/agentbus2`, `~/.local/share/agentbus2`).
- `scripts/m4-exit-checks.sh <local.log> <inproc.log>` checks the Milestone 4 exit counts and the import rule; `--deps-only` runs the import rule alone.
- `scripts/m5-exit-checks.sh <auth.log>` checks the `TestAuthEndToEnd` counts (11 leaf subtests per engine) and the Milestone 5 import rule; `--deps-only` runs the import rule alone.
- `scripts/m6-exit-checks.sh <e2e.log>` checks the `internal/e2e` counts (13 sequence steps, 11 exit-code cells), the agent-text word check and the Milestone 6 import rule; `--deps-only` runs the import rule alone. The e2e test builds the binary and runs a real server, so `make test` covers it (about 30 s, no Docker).
- `scripts/m8-exit-checks.sh <tui.log>` checks the `TestBothModes` (2), `TestNoInboxView` (1) and `TestRunTUI{Local,Server}Profile` (2) counts, the word check and the `internal/tui` import allowlist; `--deps-only` runs the import allowlist alone.
- `make docker-image` builds `agentbus2:local`; `make docker-smoke` builds it and smoke-tests it (both need Docker and are not part of `verify`; CI runs the smoke as its own job).
- `scripts/m7-exit-checks.sh <replicas.log>` checks the `TestReplicas*` counts (`TestReplicasWake` 4 leaves on SQLite and 6 on Postgres, `TestReplicasMaintenanceExclusive` 2 per engine) and the Milestone 7 import rule; `--deps-only` runs the import rule alone.
- `make check-gates-selftest` tests the gate scripts themselves (minutes; CI runs it as its own job).
- `make release-check` (the release harnesses, the local dry run and `vet-cross`), `make release-lint` (`actionlint`, `shellcheck`) and `make release-install-check` (the installer matrix in Docker) are not part of `verify`; each runs as its own CI job. `release/release.sh <tag> --windows-signing=on|off [--no-publish]` is Eric's: it signs, notarizes and publishes (`docs/release.md`).
- `scripts/m9-exit-checks.sh [--real-only]` checks the release tooling's invariants and, without `--real-only`, four mutations in a throwaway worktree (CI job `m9-exit-selftest`).

## Design

- The design decisions (made by Eric) go in the spec under `docs/superpowers/specs/` and the ADRs in `docs/adr/`. Read them before changing an interface, the Store contract, auth or the wire protocol.
- Until the first release (Eric, 2026-10-25): no work to migrate data from, or stay compatible with, earlier builds: no new database migrations for schema changes made before the release, no compatibility layers, shims, converters or deprecation paths; change the schema, wire and formats in place and recreate local data. Forward-compatible choices for after the release are still welcome.
- The Store contract is `internal/store`; the engines are `internal/store/sqlite` and `internal/store/postgres` over `internal/store/sqlstore`; the Store suite is `internal/conformance/store` and isolates Postgres tests in a schema per test. The Store serves facts (`Tx.ACL`, `Tx.ACLRowsFor`, rows) and applies no access rule: no `EffectivePermissions`, `ReadableChannels`, permission filter or implicit entry (ADR 0004 addendum "Access facts, not rules").
- `internal/bus` is the seam: the `Bus` interfaces and their domain types and errors; clients never import `internal/store`.
- `internal/core` holds the rules over the Store, one aggregate package each (`channels`, `sessions`, `messaging`, `memories`, `tasks`, `search`, `delivery`, `maintenance`) plus `rules` (pure ports), `health` and `notify`; every mutation obeys the Decision 26 rules (see Global Constraints in `docs/superpowers/plans/2026-10-21-milestone-3-core-bus.md`).
- `internal/core/access` is the one access check and the gate (Eric 2026-10-25, ADR 0011): `decide` in `decide.go` is the only code that decides who may do what to which object; `Check`, `Require` and the set forms `Channels`, `Identities` and `Holders` load the facts. `internal/core/authz.go` is gone. `TestAccessRuleSites` (`internal/core/access/sites_test.go`) fails when code outside `access` reads `Admin`, `Creator`, `Owner`, `Scope` or an identity or memory `Kind` (anywhere in a function or a package-level initializer, not only in a condition), when an `ACL(` call on any receiver has an unlisted caller or when `sqlstore` SQL filters on a flag, permission or creator column; the allowlist is a literal holding an exact count per site and clause, so adding a site or an occurrence is a visible edit (`scripts/check-gates-selftest.sh` block 29 holds a mutation per clause). The administrator gate anchor `if !p.Admin {` lives in `internal/core/access/decide.go` (once; `scripts/check-gates-selftest.sh` block 15). An ACL may name three groups, `everyone`, `admins` and `humans` (members: identities of kind human; the name is reserved), and an agent that is not an administrator never removes a permission from a protected entry (a human's, an administrator's, or a group's) in `set_acl`. The channel actions are `Read`, `Write`, `Admin`, `List` (a stored row for the principal's names, or the administrator flag: no creator clause, Eric 2026-10-26), `Unsubscribe` and `FilterReceive` (the scope gate alone), `Deliver` and `Post`; `TakeName` (the scope-prefix name rules, on `ChannelName` and `ScopeName`) is the other one. There is no implicit creator entry and no task owner guard.
- `GET /v1/health` (an open operation, 8 open and 44 protected in all; bearer optional, and the one open operation that answers 401, to an invalid bearer; operation `health`) answers a tiered document (probe, identity, administrator by the flag; 503 `store unreachable` when the store does not answer) built by `internal/core/health` and read through `Bus.Health` (the `Monitoring` interface, the sixth); `GET /v1/discover` is the liveness probe and advertises the `health` capability (`docs/ops/health.md`, ADR 0010). Discover and health carry `protocol_version` (`internal/version.Protocol`, equal to `api/openapi.yaml` `info.version`); after the first release an addition bumps the protocol minor instead of adding a capability string (until then the version stays `1.0.0`, Eric 2026-10-27). `Store.SchemaVersion` is the readiness ping.
- `internal/bus/local` is the in-process `Bus` bound to one identity; it delegates to the core.
- `internal/conformance/bus` is the Bus suite on both engines, including the ACL matrix (`TestACLMatrix`); `scripts/m3-exit-counts.sh` checks a `-v` log of it against the Milestone 3 exit counts.
- `api/openapi.yaml` is the wire protocol: read spec 3 and ADRs 0001 and 0007 before changing it, then `make generate` (it writes `internal/gen` and `internal/gen/spec`; never edit those by hand); bump `info.version` and `version.Protocol` together: minor per addition, patch for a documentation-only change. Until the first release the protocol version stays `1.0.0` and additions do not bump it (Eric 2026-10-27); the minor-per-addition and patch-for-docs rule applies after the release.
- `internal/server` holds the handlers over the core, one file per aggregate; every error goes through `WriteProblem` (problem+json) except the token endpoint's, which answers the RFC 6749 body (`internal/server/oauth.go`), and `Authenticator` is the authentication seam (`RefuseAll` by default). `internal/server/cmd` is `agentbus2 server`.
- `internal/bus/remote` is the client side of Decision 47: a `Bus` over the generated client; it never imports `internal/gen/spec`, `internal/server`, `internal/core` or kin-openapi.
- Decision 47 import rule (checked by `scripts/m4-exit-checks.sh`): `internal/bus`, `internal/core/...` and `internal/bus/local` do not import `internal/gen` or `internal/server`; `internal/server/...` does not import `internal/bus/local` or `internal/bus/remote`.
- `internal/core/notify/pgnotify` is the Postgres doorbell: a native pgx `LISTEN` connection feeding the notifier, hints only, reconnecting; `cmd.Run` wires it for a Postgres store (SQLite gets the in-process notifier). `NOTIFY` runs inside the append transaction and on watch registration (`internal/store/postgres/notify.go`).
- `Store.Locks` (`TryLock`, `Unlock`: the `leases` row on SQLite, a pinned-connection advisory lock on Postgres) guards maintenance, so one replica runs the jobs; `Store.Space` (`Usage`, `Reclaim`) feeds budget eviction and capacity notices (SQLite only).
- Schema version 1 is the whole schema (one `0001_initial.sql` per engine): the migration steps of the pre-release builds were flattened into it before the first release (Eric, 2026-10-25, ADR 0004 addendum), and a database an earlier build created (version above 1) is refused with `ErrUpgradeNeeded`, never converted. It holds the Store tables and `schema_meta` machinery plus: enrollment tokens, `signing_keys`, `assertion_jti` keyed on `(identity, jti)` (`Tx.PutAssertionJTI`, `DeleteAssertionJTIBefore`; the token endpoint consults and writes it in one transaction, so a client assertion is single-use across replicas), `identities.kind` (`agent` or `human`), `messages.sender_kind`, `human_bindings`, `access_refs` (the `users` and `admins` lists), `scopes`, the `scope` column of `channels` and `identities`, `retired_identities`, `bridges`, `bridge_messages`, `slack_users`, `bridge_dropped`, and the seeded reserved `slack-bridge` identity. Later steps (`0002` and up) are for after the first release.
- Milestone 7 import rule (checked by `scripts/m7-exit-checks.sh`): `internal/store/...` never imports `internal/core/...`; `internal/core/notify` is a leaf (no `internal/store`, no pgx); `internal/core/notify/pgnotify` never imports `internal/server` or `internal/gen`.
- Slack import rule (same script): `internal/slackapi` imports only the standard library; `internal/slackapi/slackfake` only the standard library and `internal/slackapi`; `github.com/slack-go/slack` is imported only by `internal/slackapi/slackgo` (any file: test files and every GOOS count); `internal/core/...`, `internal/bus/...`, `internal/cli`, `internal/mcpserver`, `internal/client` and `internal/server` (the package, not `server/cmd`) never import `internal/slackapi`, `internal/slackbridge` or `internal/slackapi/slackgo`. `internal/slackbridge` never imports `internal/server`, `internal/gen`, `internal/slackapi/slackgo` or slack-go.
- Scope is an access boundary for scoped agents only (ADR 0011): outside its scope an agent gets `not_found`, inside it the ACL decides; administrators and humans are never scoped and are visible to every agent. `internal/core/scopes` holds scope creation, retirement (`with_bridge` or `normal`; a scope with a live bridge and no `Archiver` is held, never retired), scoped identities and the bridged-channel ACL rules; `reply_to` is validated in `core.Append` for every channel (same channel, else `validation`) and rewritten to the thread root on a channel with a live bridge. `history` takes `thread` (complete only for replies stored after the bridge went live).
- `internal/slackapi` is the Slack port (standard library only); `slackapi/slackgo` is the one adapter over slack-go, `slackapi/slackfake` the test double. `internal/slackbridge` is the bridge (create, outbound, inbound with trust checks, catch-up, archive rules, the single runner under the `slack-bridge` Store lock); `server/cmd` wires it when both token files are set, and without them every `bridges` call is `unavailable` (not retryable). Operator guide: `docs/ops/slack-bridge.md`; decisions: ADR 0009.
- Decision 20 (ADR 0009): a subscription keeps an empty channel alive only when its holder is not `slack-bridge` and has a live or resumable session; this supersedes the empty-channel rule of ADR 0008 decision 8.
- `docs/ops/` is the operator's entry point (deploy, configuration, admin bootstrap, backup, upgrade).
- `internal/auth` (`keys`, `assertion`, `token`) is a leaf: it imports no `internal/store`, `internal/core`, `internal/server`, `internal/gen` or `internal/bus`, and `internal/bus/remote` never imports `internal/auth/token` (checked by `scripts/m5-exit-checks.sh`).
- `internal/core/identities` holds registration, enrollment tokens, the admin flag, reset and the signing-key rules; the host commands and the handlers both call it. `internal/server/config` is Decision 85's configuration.
- The server's token signing keys are Store rows (`signing_keys`: a key set with at most one `active` row and any `retiring` rows; `Tx.PutSigningKey`, `ListSigningKeys`, `RetireSigningKey`, `DeleteSigningKey`, `DeleteSigningKeysBefore`; ADR 0004 addendum "Signing keys addendum"). The first start creates the active `store` row (plaintext PEM): read access to the database equals the admin flag. Rotation is issue #6 (in progress), a key provider issue #8.
- `make verify` covers the schema (version 1) on both engines; `TestAuthEndToEnd` (`internal/conformance/bus/auth_test.go`) is the Milestone 5 exit over TCP.
- `internal/profile` is `config.json` (`profiles` of `mode` local or server, `server`, `identity`, `credential_process`, `sqlite`, `oidc` for a human's browser sign-in: server mode only, `issuer` https or loopback http, `client_id`, `redirect_port`, `scopes`) and the selection order: flag, `AGENTBUS2_PROFILE`, the nearest `.local/agentbus2.json` (`{"profile": ...}` only), then `default` (built-in local); identity: flag, `AGENTBUS2_IDENTITY`, the profile's `identity`, then the only credential file of a server profile, then, for `agentbus2 tui` on a local profile only, the OS login name (source `os-user`); with `client.Options.HumanSignIn` (the TUI and `login -human` on a server profile) no identity is selected and the identity is the sign-in's (source `sign-in`); for `tui` the profile's `identity` and the single-credential step are skipped when the repository file selected the profile (`client.Options.HumanIdentity`), so the human never shares the agent's identity. `internal/repoconfig` reads the repository file.
- `internal/credential` holds the credential files (`<config dir>/credentials/<profile>/<identity>`, PKCS#8 PEM, 0600), the `credential_process` protocol (version 1 JSON on stdin and stdout, 10 s, never from the repository file) and the bearer cache (`<data dir>/tokens/<profile>/<identity>.json`, used until 60 s before expiry); the transport (over the `TokenSource` interface) invalidates and refreshes once on a 401. `HumanSource` and `HumanCache` (`<data dir>/tokens/<profile>/human/session.json`, 0600) are a human's cached server bearer plus the provider's refresh token (cached bearer, else `oidcclient.Refresh` and the exchange, else the browser); the corporate token is never stored.
- `internal/client` builds one `bus.Bus` per profile: a local profile runs the core and the HTTP handler in this process over the SQLite file behind the in-process transport (the maintenance loop runs only in `agentbus2 mcp` and `agentbus2 tui`), a server profile dials the server with a minted bearer.
- `internal/sessionstate` is the per-session state file `<data dir>/sessions/<session>.json` (0600; harness reference, profile, identity, resume token, `primary`, `parked`). It survives the MCP server's exit; `close_session` or the start-up sweep (harness also dead) removes it. `watch`, `wait` and the hooks read it through `procs.FindHarness`; a session from a state file binds them to the file's profile and identity, and a disagreeing `-profile` or `-identity` is exit 2.
- Agents never receive memory channels (decision 20): the rule is the `Deliver` action of `internal/core/access`, enforced on the server in `Receive`, `Peek` and `Watch` for an agent principal (so the Stop hook's count, `wait`'s wake and `receive -session` need no client filter), and an agent's subscribe to a memory channel answers `validation` there. The Bus and the TUI are unfiltered because the TUI's identity is human.
- `internal/mcpserver` has hand-written tool schemas and never imports `internal/gen`. The Stop hook counts through the read-only `peek` operation, so it never re-blocks for a batch the agent already holds.
- `internal/tui` runs over `bus.Bus` only, the entry (`run.go`) included: of this module it imports `internal/bus` and `internal/version` and nothing else (allowlist in `scripts/m8-exit-checks.sh`); `internal/cli/tui.go` opens the `Bus` through `client.Open` and passes it in. Its settings are the `tui` object of `config.json` (`profile.Config.TUI`). Rail sections come from channel `Kind`; `tags:` is the one synthetic rail prefix and never reaches the bus. The stub-then-replace file layout of the port is history, not a rule.
- Milestone 6 import rule (checked by `scripts/m6-exit-checks.sh`, direct imports of non-test code): `internal/profile`, `repoconfig`, `credential`, `procs` and `sessionstate` do not import `internal/core`, `internal/server`, `internal/bus/local` or `internal/store/{sqlite,postgres,sqlstore}`; `internal/mcpserver` and `internal/cli` do not import `internal/gen` or `internal/store`; `internal/oidcclient` (the browser sign-in client) and `internal/oidctest` (the fake provider) import no package of this module.
- `release/` is the release tooling, ported from v1 `release/`; `release/build-archive.sh` is the one command that builds a release archive (the workflow, `release.sh` and the dry run all call it). Docs: `docs/install.md`, `docs/release.md`, `docs/release-signing.md`.
- v1 code is ported deliberately: the commit message names the v1 source file. Do not port artifacts of decisions v2 changed (DMs, identity derived from the harness, `-filter`).
