# Server Health Implementation Plan (issue #11)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `GET /v1/health` answers a tiered health document (probe, identity, administrator) and 503 when the store is unreachable; `/v1/discover` is the liveness probe and advertises the `health` capability; the `Bus` gains `Monitoring.Health`, implemented locally and remotely and covered by the conformance suite on both engines and both transports; the TUI health overlay and a new MCP tool `health` read it; `docs/ops/health.md` documents it.

**Architecture:** `store.Store` gains `SchemaVersion` (already implemented by `sqlstore`); `core.Core` records this process's last maintenance tick and its start time; a new aggregate `internal/core/health` builds the document from the Store, the notices, the embedding report shared with `channels.Status`, `channels.Usage` and the tick record, tiered by the caller's identity row (Decision 73); the handler, the local and the remote `Bus` are thin over it. No schema change, no new setting, no change to any decision Eric made.

**Tech Stack:** Go 1.27, kin-openapi + oapi-codegen (`make generate`), modernc SQLite and pgx Postgres, testcontainers for the Postgres suites, Bubble Tea (TUI), the MCP Go SDK.

**Spec:** `docs/superpowers/specs/2026-10-25-health-design.md` (agent design of 2026-10-25; every "Agent decision (pending Eric's review)" is to be implemented as written and may be overturned by Eric in the morning, so keep each one easy to reverse: no decision is spread across files beyond what the spec names). Read it in full before any task; section numbers below refer to it.

## Review Focus

1. The probe tier leaks nothing an administrator alone may read today: no notice text, no error text, no owner, no storage figure, no engine or schema version below the identity tier (Task 4 `TestHealthProbeTier`, Task 4 conformance `TestHealthTiers`).
2. A rejected bearer is 401, never the probe tier; a bearer for a deleted identity is 403 `not_registered`, never a document (Task 4 `TestHealthBadBearerIs401`, `TestHealthUnregisteredIdentity`).
3. A closed or unreachable store answers a 503 problem with `code: unavailable`, `retryable: true` and a message without the DSN, on both the local and the inproc leg, and `remote.Bus.Health` returns that as a `*bus.Error` (Task 4 `TestHealthStoreDownIs503`, `TestHealthUnavailableError`).
4. The maintenance block is this process's view: `lock: unknown` before any tick, `held` after a tick that took the lock, `held_elsewhere` in a second core over the same database, and never a schema change (Task 2 `TestTickRecordsLastTick`, Task 4 conformance `TestHealthMaintenanceBlock`).
5. The 24-to-25 tool count moves in every pinned place at once, and the e2e counts do not move (Task 5; Task 8 runs `bash scripts/m6-exit-checks.sh` on a fresh e2e log).
